# Working on OpenTodo (guide for AI coding agents and humans)

## What this is
Open-source, self-hosted, local-first task manager that replaces subscription task apps. Go server + SQLite, React PWA embedded in the binary, field-level op-log sync. AGPL-3.0.

## Non-negotiables
1. **Specs before behavior.** Behavior changes start as an OpenSpec change (`openspec/changes/<name>/`). Use `/opsx:propose`, `/opsx:apply`, `/opsx:archive`. Live specs are in `openspec/specs/`. Validate with `make openspec-validate` (the OpenSpec CLI at the exact version pinned in the `Makefile`).
2. **All data writes go through ops.** Membership is never an op; REST writes use `ApplyStrict` and wake devices with `NotifyApplied`. Never write task/project rows directly. Server: `internal/sync`. Client: `web/src/lib/ops.ts` → `mutate()`.
3. **Op schema is additive.** New fields: add to `internal/sync/ops.go` `Schema`, `web/src/lib/types.ts`, and the defaults in `web/src/lib/ops.ts`. Never rename or remove a field without a design doc. New user-written string fields must also be added to `internal/e2ee.ContentFields` and `CONTENT_FIELDS` in `web/src/lib/e2ee.ts`; server features that show content use `e2ee.Display`/`IsCiphertext` and degrade explicitly.
4. **Auth required by default.** Every route is registered through the policy wrapper `routes.handle(pattern, policy, handler)` in `internal/httpapi/policy.go` with one declared policy (`signedIn`, `ownerOnly`, `adminsOnly`, or `public("reason")` only when a spec says so; modifiers `.credential()`, `.recent()`, `.sensitive()`, `.sessionOnly()`, `.fullTokens()`, `.demoDenied()`); never call `ServeMux.Handle` directly, `policy_test.go` fails on it. Routes that could be abused on a public demo instance (outbound requests, credentials, settings, members, bulk writes) get `.demoDenied()` and a matching entry in the deny list in `internal/httpapi/demo.go` (the test checks both agree). API tokens have a scope `full`|`read`|`agent`|`admin` (side tables `api_token_scopes`, `api_token_agent`, `api_token_admin`): `read` tokens are refused on writes and `/api/v1/sync`; `agent` tokens write only through the agent content routes and MCP write tools; `admin` tokens can do what `full` can plus the credential and administration routes (second factor, passkeys, tokens, app passwords, user administration, SSO and secret-holding settings, encryption key record), which refuse `full` tokens. Admin tokens are created only from a recently confirmed session.
5. **No telemetry, no third-party network calls, no new mandatory env vars.** Outbound requests go only to targets the operator or a user configured (webhooks, backup destinations, push services, the OIDC issuer, the SMTP server, the IMAP mailbox, assistant model providers, calendar subscriptions); addresses a person typed go through `internal/outbound`.
6. **Keep it small.** Justify every dependency. Report bundle / binary size impact in design docs.

## Layout
- Server core: `cmd/opentodo` entry point (`cmd/ot` is the CLI, `internal/cli`: profiles, REST calls, table and `--json` output); `internal/config` env (`OPENTODO_*`, nothing mandatory); `internal/store` SQLite + embedded migrations (`internal/store/migrations/NNNN_*.sql`, applied by `PRAGMA user_version`), one writer connection plus a query-only reader pool (`store.OpenReader`, installed with `sync.Service.SetReader`): pure reads may use the reader, anything that reads then writes in one transaction stays on the writer; `internal/tenant` builds one server around one data directory (database and lock, services, notifier, HTTP handler, background jobs); `internal/host` optionally serves many tenants from one process (registry, host-name routing, lazy open and idle close, one scheduler, per-tenant limits, the operator interface; only built with `OPENTODO_HOST_URL`); `internal/sync` op log + LWW + materialized reads, sharing scopes (`scope.go`) and membership (`members.go`); `internal/httpapi` router/handlers/middleware (route policies in `policy.go`, demo deny list in `demo.go`); `internal/web` embeds `internal/web/dist`; `internal/ids` UUIDs, name-based ids and random secrets.
- Accounts and security: `internal/auth` users/sessions/tokens and their scopes, invitations, TOTP and recovery codes, passkey storage, provider identities, CalDAV app passwords (`internal/auth/apppasswords.go`); `internal/webauthn` passkey verification (clientDataJSON, authenticator data, COSE keys; `internal/webauthn/testauth` is a synthetic authenticator for tests); `internal/oidc` single sign-on (discovery, PKCE, ID-token verification, `OPENTODO_OIDC_*` overrides; `internal/oidc/oidctest` is an in-process provider for tests); `internal/audit` the closed catalogue of security events (typed constructors, an allow-list for details so task content never reaches the log, NDJSON export, retention); `internal/e2ee` end-to-end encryption helpers (content field list, ciphertext detection, key-record store; no crypto on the server; client in `web/src/lib/crypto.ts`, `e2ee.ts`, `e2eeSync.ts`); `internal/outbound` the policy for every request to an address a user or the owner typed (http(s) only, no private network targets unless the owner allows them, the connection pinned to the checked address; used by webhooks, and through their client by push and the assistant, and by calendar subscriptions); `internal/demo` the public demo instance (`OPENTODO_DEMO=true`: a hidden owner, a private short-lived sandbox per visitor seeded through the op log, the nightly reset; HTTP side in `internal/httpapi/demo.go`).
- Features: `internal/settings` owner settings and secrets files; `internal/backup` snapshots, archives, destinations, scheduler, restore; `internal/push` VAPID keys, RFC 8291 encryption, subscriptions and the reminder scheduler (service worker side in `web/public/push-sw.js`); `internal/notify` notification sinks (in-app inbox; new event kinds go through optional sink interfaces such as `notify.MentionSink`); `internal/activity` derives activity events from ops and must match `web/src/lib/activity.ts` (shared fixture `internal/activity/testdata/activity_fixture.json`); `internal/webhook` signed outbound notifications for task and project events (derived from committed batches, durable queue in SQLite, one worker with retries, SSRF-safe client); `internal/caldav` iCalendar/VTODO mapping and WebDAV XML (handlers in `internal/httpapi/caldav*.go`, writes via `ApplyStrict` with device `caldav:<app-password-id>`); `internal/calfeed` calendar feeds (other people's calendars read into read-only events, the user's tasks written as a calendar); `internal/email` email to task (optional IMAP polling of one operator mailbox via `OPENTODO_EMAIL_*`, stdlib MIME and IMAP, per-user secret sub-addresses, Message-ID receipts; tasks via `ApplyStrict` with device `server`); `internal/mail` optional outgoing email (owner SMTP configuration with `OPENTODO_SMTP_*` overrides, stdlib transport with an explicit TLS policy, plain-text templates in six languages, sending limits; every message goes through `Service.Send`; `internal/mail/smtptest` is an in-process SMTP server for tests); `internal/digest` the opt-in weekly email digest (per-user settings, scheduler on the jobs leader, content from materialized rows); `internal/importer` own export, CSV and other apps' exports into ops (profiles to rows, planner, background jobs with undo, device `import`; `internal/importer/sanitize` is a command that turns a real export into a test fixture and is never linked into the server); `internal/blobs` attachment bytes as immutable files under `<data>/attachments/` (size and SHA-256 checked, streamed, never read whole).
- AI agents: `internal/agenttools` the one registry of tools an AI agent can call (definitions, argument validation, planning into change sets, untrusted-text marking, write limits, the write permission gate, `agent.write` audit, the per-user "Allow AI assistants to make changes" switch in `user_agent_access`); `internal/mcp` the MCP server over that registry: read tools and read-only `opentodo://` resources behind the owner toggle `mcp.enabled`, and write tools only when the owner's `mcp.writes` switch and the user's switch are on and the caller uses an `agent` token (writes via `ApplyStrict` with device `agent:<token-id>`; transport in `internal/httpapi/mcp.go`); `internal/assistant` the in-app assistant (owner configuration and provider keys, per-user consent and token usage, the Anthropic SDK and one stdlib Chat Completions adapter, an agent loop that runs read tools and plans write tools but never writes: the browser shows the proposed change set and applies the confirmed part through `mutateMany` with device `assistant:<device-id>`).
- Go ports of web logic, each pinned by shared vectors: `internal/recurrence` (`web/src/lib/recurrence.ts`), `internal/zoned` time-zone-fixed due values (`web/src/lib/dates.ts`), `internal/filter` the filter query parser (validates saved views; evaluation stays on the client), `internal/quickadd` the quick-add parser (`web/src/lib/nlp`; used by the CLI and the importer).
- `web/` Vite + React 19 + Tailwind 4 + Dexie. `src/lib` data layer (db, ops, sync, hlc, api, dates), `src/app` UI, `src/ui` shared building blocks (Icon, Button, Field, Switch, Menu items, Combobox, Card, Badge, Avatar, Tabs, patterns; each with stories). Tests: `*.test.ts` with vitest + fake-indexeddb; interaction tests opt into `// @vitest-environment happy-dom`.
- `extension/` browser capture extension (MV3, plain JS; `make extension` builds the zip).
- `docs/` architecture, sync protocol, API, self-hosting. `ROADMAP.md` maps features to change names.

## Commands
- `make dev` (API :8080 + Vite :5173), `make check` (what CI runs), `go test ./...`, `cd web && npm test && npm run build`.
- Build the web app before `go build` or tests that import `internal/web` (`make web`); `internal/web/dist/.gitkeep` keeps the embed compiling on a fresh clone.
- Manual smoke: `./bin/opentodo` then open http://localhost:8080; first visit creates the owner account.

## Conventions
- Go: stdlib `net/http` mux with method patterns, JSON error envelope `{error:{code,message}}`, `slog` logging, errors wrapped with context. Functions stay under 150 lines and files under 1,100 (`internal/codesize`, a test-only package); HTTP handlers live by area in `internal/httpapi` (`router.go` registers every route, then `middleware.go`, `auth_handlers.go`, `collections.go`, `sync_handlers.go`, …).
- TS: strict, function components, Tailwind classes, data access only via `src/lib`. Custom CSS classes live in `@layer components` so utilities can override them.
- Design: colours, type, radius, elevation and motion come from the tokens in `web/src/index.css` (no raw palette classes or hex in `web/src/ui`); shared UI is built and checked in the Storybook workbench (`make storybook`, `make ui-check`). Screens use primitives from `web/src/ui`, never emoji or glyphs as icons (`<Icon>`, enforced by `make ui-lint`), and choose entities (people, labels, projects, tasks) with the Combobox. See `docs/design-system.md`.
- Dates: `due` is a floating `{date: "YYYY-MM-DD", time?: "HH:MM"}`; timestamps are Unix milliseconds.
- Priority: 1 = highest … 4 = default/lowest.
- Deletion is a tombstone (`deleted_at`); lists filter it out, export includes it.
